## 0 · 决策摘要（一段话版）

**架构基线 = TradingAgents-CN（后端 + 内核）+ TauricResearch/TradingAgents（上游同步）后端复合 + 前端自主构建**（不 fork SD；SD 仅作视觉参考），附 **A/B 双轨**：

- **A 轨（首选，依赖 CN 商授通过）**：fork CN（含 `app/` 闭源后端商授使用），**前端基于 spec + DESIGN.md 自主构建**，月度 cherry-pick TR 上游 `tradingagents/agents/` 与 `graph/` 改进。预估改造 **~30 人日**（前端自建工作量上调，见下）。
- **B 轨（兜底，商授失败时）**：仅用 CN 开源内核 `tradingagents/`（Apache-2.0）+ TR 上游同步，**前端自主构建 + 自建 FastAPI 轻量后端**。预估改造 **~40 人日**。

**借鉴层（非 fork）**：go-stock 的钉钉/飞书推送模式 + 阈值告警逻辑，重写避 GPL（3-5 人日）；ai-hedge-fund 的投资大师 prompt（11 个直接可用 + 改造可用，v2 可选 port）。

**被否方案**：go-stock 单 fork（商业 GPL 自杀已被 owner 自承）/ ai-hedge-fund 单 fork（美股化净改造 46 人日反超 CN）/ stock-dashboard 单 fork（owner 从未主张）/ TauricResearch 单 fork（Plan B 不可主推）/ 全自建（62 人日 vs CN 路线 30-40 人日数据反驳）/ Dify-Coze 低代码（保留为 Plan C，仅 PMF 验证）。

## 2 · 被否方案理由（每条引用辩论记录）

### 2.1 go-stock 单 fork —— ❌
**驳倒证据**：advocate-fullstack 自承（`responses-advocate-fullstack.md` E-Q1 §"立场退"）："商业闭源路线下，go-stock 不应 fork，只应借鉴"。E-Q2 自承"撤回 §2 第 8 点（MCP）作为 fork 论证"。
- GPLv3 方案 A（整体开源）= 商业自杀（自承）
- 方案 B（重写 LLM 抽象）= 5-8 人日（修正自 3 人日）
- 方案 C（双重许可）= 无 paper 内证据，撤回
- 桌面 → Web 改造 12-18 人日，仅在"Go 栈"前提成立（与 04-实现方案 Python 既定栈冲突）

### 2.2 ai-hedge-fund 单 fork —— ❌
**驳倒证据**：advocate-fullstack 修正后总改造 **46 人日**（red-team A-Q3 让 advocate 算账：原 30 + 美股语义清洗 6 + 合规改造 3 + ClickHouse 实时层 7 = 46）。
- 净对比从零写 30 + 23（fork 白拿）= 53，advocate 自承 fork 仅便宜 7 人日 —— **不构成单 fork 决定性优势**
- advocate 同条自承"承认组合 15（CN+GS+AHF 借鉴）是更稳健路线"
- "Educational Only" 自定位虽 MIT 可重写 README，但叠加证监会合规风险

### 2.3 stock-dashboard 单 fork —— ❌（owner 从未主张）
**澄清证据**：`responses-advocate-frontend.md` Integration-Challenge §"我的 paper 从未主张 SD 单 fork —— 第 7 节'推荐全家桶'白纸黑字写的就是 SD + TradingAgents-CN backend + TR 上游..."
- SD 作为**前端运行时基线**通过（红队 C-Q1 stock-sdk 证据链闭合：ISC、同人维护、4 天前活跃）
- SD 作为**全栈方案**伪命题，无 owner 主张

### 2.4 TauricResearch/TradingAgents 单 fork —— ❌（Plan B 不可主推）
**驳倒证据**：advocate-langgraph 自承（`responses-advocate-langgraph.md` Integration-Challenge §"TR 单 fork 是 Plan B：商授谈崩 / 长期 bus-factor=1 顾虑 / 强法务合规要求时的兜底，非主推"）。
- TR 单 fork 总改造 **45-47 人日**（含 checkpoint 多租户化 6-8 + A 股化 8-12）
- 等同放弃 CN 27k★ 已完成的中文 prompt + A 股 dataflows 工程化（与 TR 同 Apache-2.0 同源可直接复用）

### 2.5 全自建 —— ❌
**驳倒证据**：`integration-assessment.md` 全自建对照分仅 **5.0 分**（62 人日 vs CN-based 30-40 人日）。集成评估师明确表态"全自建不支持红队'全自建'立场"。
- 红队 Phase 1 主张未被任何一条工程数据支持
- 红队 Plan C（Dify/Coze 低代码）保留为 PMF 验证阶段独立路径，**不替代 MVP 工程**

### 2.6 Dify/Coze 低代码 —— ❌作 MVP，✅保留为 Plan C
- 适合纯 PMF 验证（1-2 周），不适合 7×24 多用户 SaaS（异动检测延迟 / 推送限频 / 自选股多租户）
- 决议：**新立项前 1 周用 Dify 跑通"自选股 + LLM 选股 + 飞书推送"全链路验证用户需求**，然后再启动 fork 工程

## 3 · 关键事实修正（Phase 2 浮现，必须入决议）

### 3.1 TradingAgents-CN 闭源范围（红队 + 集成评估师 + advocate-langgraph 一致确认）
**纠正前**：integration-assessment.md Phase 1 假设"app/frontend 闭源占比 <15% 边角"
**纠正后**：闭源 = `app/`（整个 FastAPI 后端含 api/ws/auth/batch）+ `frontend/`（整个 Vue3 前端），是**后端 + Web 前端两大支柱**，需邮件 hsliup@163.com 商授。`tradingagents/` 内核 Apache-2.0 开源。

**对决策的影响**：
- A 轨 fork CN backend 必须发邮件询商授（费率与回应时间未知）
- 即便商授失败，CN 27k★ 价值不归零 —— 中文 prompt + A 股 dataflows 内核仍是 Apache-2.0 可直接复用

### 3.2 stock-sdk 实际是 ISC 公开包（advocate-frontend C-Q1 证据闭合）
**纠正前**：red-team Phase 1 攻击"依赖私有 stock-sdk"
**纠正后**：`registry.npmjs.org/stock-sdk` 实测 license=ISC、repo=github.com/chengzuopeng/stock-sdk.git、作者=chengzuopeng（与 dashboard 同人）、latest=1.9.2、发布于 2026-05-16

**对决策的影响**：
- SD 数据层依赖风险 = 0（同人维护，作者放弃 SDK 概率 ≈ 放弃 dashboard 概率）
- 通过 `services/sdk.ts` 单点适配改 fetch 自建后端 endpoint，1-2 人天

### 3.3 GPLv3 重写真实成本（red-team E-Q1 → fullstack 接受修正）
**纠正前**：fullstack paper §6 "GPLv3 处理 0-30 人日上界"
**纠正后**：商业闭源路线下重写 LLM 抽象 + 推送 + 异动等 GPL 模块 ≈ 15-20 人日（advocate 自承"等价于几乎从零写"）

**对决策的影响**：
- go-stock 退为"借鉴推送/告警思路重写"，不 fork

### 3.4 TR checkpoint 多租户化成本（red-team B-Q3 → langgraph 接受修正）
**纠正前**：langgraph paper §5 "ClickHouse+Redis+PG 4 人日"
**纠正后**：含 LangGraph `BaseCheckpointSaver` 改 PG/Redis（pip `langgraph-checkpoint-postgres` 可用）+ 多租户隔离 + memory.md 改 PG JSONB + 数据迁移 ≈ 6-8 人日

**对决策的影响**：
- TR 单 fork 总改造从原 39 上调至 **45-47 人日**
- A 轨 + B 轨成本估算已含此项

## 4 · Open Questions（必须在 brainstorming 阶段回答）

### Q1：CN 商授费率与回应时效（决定 A/B 轨）
**行动**：立项后 **第 1 周内** 邮件 hsliup@163.com，询价 + SLA。预案：
- 商授 < 5,000 元/年 + 回应 < 7 天 → 走 A 轨
- 商授 > 5,000 元/年 / 回应 > 14 天 / 无回复 → 走 B 轨
- 询价同时附书面 license 范围确认（`tradingagents/dataflows/` 是否限商授边界，参考红队 B-Q1 攻击）

### Q2：团队技术栈选定（Python or Go）
**当前事实**：04-实现方案 既定 Python（FastAPI + Prefect + akshare + LangGraph）。
**重新确认**：本决策强化 Python 选择。go-stock Go 路线 advocate 已自承"Python 栈下让位于 ai-hedge-fund"，不再是矛盾选项。
**仍需决议**：若团队后期决定引入 Go 微服务（如高并发 WS 网关），是否复用 go-stock 推送模块？建议**否** —— Python 栈一致性优先于"借鉴 5.8k★ 项目"的边际收益。

### Q3：License 风险容忍度（决定是否需要 license 律师审核）
**当前混合**：
- CN：Apache-2.0 + 商授双协议（A 轨需书面 license）
- SD：仓库无 LICENSE 文件（需问作者补；fallback：基于 SD 设计语言重写）
- stock-sdk：ISC（无问题）
- TR：Apache-2.0（无问题）

**建议**：MVP 阶段成本可控，无需聘律师；商用前（用户 > 1000 或对外收费）必须做完整 license audit + 与 hsliuping/chengzuopeng 双方书面确认。

### Q4：是否在 v2 引入 ai-hedge-fund 投资大师 prompt
**当前判断**：MVP 不引入（净改造 7 人日收益不显著）。
**v2 触发条件**：用户提出"投资人格风格分析"需求时（vs 单纯"基于因子选股"），port 11 个 A 股可用人格，v2 阶段 5-7 人日。

### Q5：MCP server 路线是否并行（红队 Plan C 残留）
**当前判断**：MVP 先按传统 SaaS（FastAPI + Web Dashboard）走。
**v2 触发条件**：用户问"能否把你的选股能力暴露给我自己的 Claude Code/Cursor？" → 1-2 人日加 MCP server 即可，**不影响主架构**。

## 6 · 风险（Phase 3 综合）

### 6.1 新增风险（来自辩论）
1. **CN 商授不可获得**：触发 B 轨，工程量上浮 ~10 人日 + 失去 CN app/ 已验证的 watchlist/analysis_jobs 数据模型
2. **SD 仓库无 LICENSE 文件**：MVP 期间需问作者补；fallback 基于设计语言重写（5-7 人日额外）
3. **CN bus-factor=1**：作者 hsliuping 一人维护，需准备 TR 单 fork 作长期回退方案

### 6.2 沿用 v1 风险（不变）
- Tushare Pro "非商业化"协议 → 个人 App 灰度可行，对外卖订阅违约
- AkShare 上游 2026-03 已合规整改 → 必须 `AkShare → efinance → Tushare 实时分钟` 降级
- MiniQMT 10 万门槛过滤 60% 用户
- 用户量 > 1 万 / 对外收费 → 必须采购 Choice 5,800-18,000 元/年
