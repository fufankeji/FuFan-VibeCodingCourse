## 1. 为什么做这个功能（Why）

PRD §2.1 第 2 痛点：持仓股突变 / 自选股突破 / 重大公告 4 类信号靠人工监控不可靠，盘中常常事后才知道。F2 是产品的**主动监控核心**：7×24（交易时段）自动扫描自选股，命中规则即经 F3 解释 + F6 推送，让用户"即使不在屏幕前也不错过"（US-02）。

F2 同时是 F1 异动徽章的**数据来源**：F1（方案 A）预留的徽章位由 F2 的规则引擎回填。

## 2. 功能边界（What）

### 2.1 In-Scope（F2 必做）

- **价格/量能规则引擎**（交易时段每 60 秒扫描自选股）：涨停、跌停、涵盖（突破前 60 日新高/跌破新低）、量能异常（量比 > 5 日均量×3）、振幅异常（日内振幅 > 8%）
- **事件规则引擎**：财联社电报红色/紧急标签 + 交易所公告，按自选股相关性匹配（业绩/分红/重组/减持/监管处罚/重大合同等关键事件）
- **异动状态与转换检测**：维护每只股当前异动状态，仅对**新出现**的异动触发推送（避免持续涨停每 60 秒重复调 LLM）
- **优先级**：持仓股 > 自选股（板块异动 v1.1）
- 命中新异动 → 调 F3 生成解释 → 组装卡片内容 → 调 F6 推送
- **持仓股强制推送**（绕过 dedup）
- 数据延迟 > 5 分钟时暂停价格规则扫描 + 告警
- 用户可开关某一类异动规则
- 对外暴露每只股当前异动徽章，供 F1（003）回填
- 订阅 F5 删除事件，停止被删股的扫描

### 2.2 Out-of-Scope（F2 不做 / 推迟）

- ❌ **板块整体异动**（概念热/资金流榜）→ v1.1
- ❌ **推送通道本身**（限频/重试/合并/未送达）→ F6（002）
- ❌ **LLM 解释生成** → F3（004）
- ❌ **卡片渲染/发送** → F6（002）的 card_renderer；F2 只提供卡片内容字段
- ❌ **发送级 dedup/合并** → F6（002）负责；F2 负责"新异动"转换检测（不同层）
- ❌ **早盘简报** → F4（006）
- ❌ **自定义规则编辑器**（用户自己写规则表达式）→ v2；MVP 规则固定 + 阈值可配

### 2.3 MVP 约束

- 扫描间隔 60 秒（与分钟级数据源一致）
- 仅交易时段（9:30-11:30/13:00-15:00）扫价格规则；事件规则可全天扫
- 异动规则固定 5 类价格/量能 + 事件类；阈值（振幅 8%/量比 3 倍/窗口 60 日）默认值可配
- 单用户、自选 ≤30 只
- ST 板涨跌停按 ±5% 判定，主板 ±10%，创业板/科创板 ±20%

### 2.4 运行环境

- 本地 Mac 常驻，交易时段 caffeinate 防睡眠（PRD §7.2）
- 行情来自 F1 quote_service；新闻/公告来自 F3 news_source
- 推送经 F6；解释经 F3

## 3. 用户场景与验收

### User Story 1 — 价格/量能异动推送（Priority: P1）🎯 US-02 核心

作为本人，当持仓/自选股发生涨跌停、涵盖、量能或振幅异动时，我希望 60 秒内收到带解释的飞书推送。

**Why this priority**：F2 的核心价值，主动监控的直接兑现。

**Independent Test**：mock 一只自选股行情触发"涨停" → 验证 60 秒内产生一条异动信号 → 调 F3（可 mock）→ 调 F6（可 mock）发出卡片。

**Acceptance Scenarios**：

1. **Given** 自选股 X 在某扫描周期首次触及涨停，**When** F2 扫描，**Then** 60 秒内检测到"涨停"新异动，调 F3 拿解释，经 F6 推送含股票名/代码/价/涨跌幅/异动类型/解释/时间戳/Dashboard 跳转链接的卡片。
2. **Given** X 持续涨停（已推送过），**When** 下一周期再扫到涨停，**Then** **不重复推送**（状态未变化，非新异动），也不重复调 F3。
3. **Given** X 从涨停打开又封回，**When** 状态变化（涨停→非涨停→涨停），**Then** 第二次封板视为新异动可再推（受 F6 dedup 5 分钟窗口约束）。
4. **Given** 量比 > 5 日均量×3，**When** 扫描，**Then** 触发"量能异常"信号。

### User Story 2 — 事件异动推送（Priority: P1）

作为本人，当自选股出现重大公告或财联社紧急电报时，我希望收到推送。

**Acceptance Scenarios**：

1. **Given** 财联社红色电报提及自选股 X（名/代码/行业匹配），**When** F2 事件扫描，**Then** 触发"事件"异动，经 F3+F6 推送。
2. **Given** 同一事件已推送，**When** 重复抓到，**Then** 不重复推送（F6 dedup + F2 事件去重）。
3. **Given** 非交易时段出现自选股重大公告，**When** 事件规则扫描（全天运行），**Then** 仍可推送（区别于价格规则仅交易时段）。

### User Story 3 — 持仓优先与强制送达（Priority: P1）

作为本人，我希望持仓股异动享最高优先级且不被去重吞掉。

**Acceptance Scenarios**：

1. **Given** 同一周期持仓股 Z 与自选股 Y 均异动，**When** 入推送队列，**Then** Z 优先级高于 Y。
2. **Given** 持仓股 Z 同信号 5 分钟内再次触发，**When** 推送，**Then** 仍送达（PushRequest 标 priority=持仓，F6 绕过 dedup）。

### User Story 4 — Dashboard 徽章回填（Priority: P1）🎯 兑现方案 A

作为本人，我希望 F1 Dashboard 的异动徽章在 F2 落地后亮起来。

**Acceptance Scenarios**：

1. **Given** F2 规则引擎判定 X 当前"突破"，**When** F1 读取异动徽章接口，**Then** X 的徽章位回填为"突破"（枚举：涨停/跌停/涵盖/突破/量能/空）。
2. **Given** X 异动消失，**When** 下一周期，**Then** 徽章位回落为空。

### User Story 5 — 规则开关与延迟保护（Priority: P2）

作为本人，我希望能关掉某类异动（如关"量能异常"），且数据延迟时系统不基于过期数据误报。

**Acceptance Scenarios**：

1. **Given** 用户在设置关闭"量能异常"规则，**When** 扫描，**Then** 不再产生量能异动信号，其他规则照常。
2. **Given** 行情数据延迟 > 5 分钟，**When** 扫描周期到，**Then** 暂停价格规则扫描 + Dashboard 告警，恢复后继续。

### Edge Cases

- **停牌/退市/新股无数据**：跳过价格规则扫描（无有效行情），不误报。
- **一字涨停（开盘即封）**：首次扫描即检测涨停，正常触发。
- **ST 股 ±5% 边界**：涨跌停判定按板块类型取对应阈值（主板 10%/创业科创 20%/ST 5%）。
- **单股同周期多规则命中**（如涨停+量能）：合并为一次推送、多个异动标签（F6 合并卡片）。
- **单周期大量异动**（如普涨 20 只）：交给 F6 批量合并（≤10 股/卡）。
- **F3 解释超时**：F2 不阻塞，推送裸卡片（无解释），日志记录。
- **F6 推送失败**：F2 不管重试（F6 的未送达队列负责）。
- **删除股票后仍在扫描队列**：订阅 F5 删除事件即时移除，避免删后仍推送。

## 4. 功能需求（Functional Requirements）

- **FR-001**: 系统 MUST 在交易时段每 60 秒扫描全部自选股行情，执行价格/量能规则（涨停/跌停/涵盖/量能/振幅）。
- **FR-002**: 系统 MUST 执行事件规则：财联社红色/紧急电报 + 公告按自选股相关性匹配（可全天运行）。
- **FR-003**: 系统 MUST 维护每只股异动状态，仅对**新出现**的异动触发推送（状态转换检测）。
- **FR-004**: 系统 MUST 按板块类型取涨跌停阈值（主板 10%/创业科创 20%/ST 5%）。
- **FR-005**: 系统 MUST 对命中新异动调 F3 生成解释，组装卡片内容，调 F6 推送。
- **FR-006**: 系统 MUST 给推送标优先级（持仓 > 自选），持仓股标 priority=持仓 使 F6 绕过 dedup。
- **FR-007**: 系统 MUST 对外暴露每只股当前异动徽章（枚举），供 F1 回填。
- **FR-008**: 系统 MUST 支持用户开关每一类异动规则。
- **FR-009**: 系统 MUST 在行情数据延迟 > 5 分钟时暂停价格规则扫描并告警。
- **FR-010**: 系统 MUST 订阅 F5 删除事件，停止被删股的扫描与待推送。
- **FR-011**: 系统 MUST 在 F3 解释失败/超时时仍推送裸卡片（不阻塞）。
- **FR-012**: 系统 MUST 跳过停牌/退市/无有效行情的股票，不误报。
- **FR-013**: 系统 MUST 提供异动阈值（振幅/量比/窗口）的可配置默认值。
- **FR-014**: 系统 MUST 对单股同周期多规则命中合并为一次推送、多异动标签。

---

## 5. 关键实体（Key Entities）

- **异动规则（AnomalyRule）**：规则定义。属性：规则名（涨停/跌停/涵盖/量能/振幅/事件）、类型（价格/量能/事件）、阈值参数、是否启用。
- **异动信号（AnomalySignal）**：一次命中结果。属性：股票代码、异动类型（= F1 徽章枚举）、触发时刻行情、是否新异动、优先级。
- **异动状态（AnomalyState）**：每只股当前所处异动集合（用于转换检测 + F1 徽章回填）。
- **规则配置（RuleConfig）**：用户的规则开关 + 阈值覆盖。
- **扫描周期（ScanCycle）**：一次 60 秒扫描的元信息（时间、股票数、数据时效、是否暂停）。

## 6. 集成边界

- **依赖 F1（003）**：行情快照（quote_service）、60 日高低（kline_service）、交易时段判定（trading_calendar）。
- **依赖 F5（001）**：自选清单读取；订阅删除事件（watchlist_events）停扫描（FR-010）。
- **依赖 F3（004）**：命中新异动调 `explain()` 拿解释（同步，超时则裸卡片，FR-011）；事件规则复用 F3 的 news_source。
- **依赖 F6（002）**：调 `push_service.send(PushRequest)` 推送；F6 负责 dedup/合并/重试/未送达；F2 传 priority + dedup_key（code+signal）。
- **向 F1（003）暴露**：异动徽章接口（FR-007），F1 每刷新周期读取回填。
- **dedup 分层**：F2 做"状态转换检测"（同状态不重复 act），F6 做"发送级 dedup"（同 code+signal 5 分钟）—— 两层互补。

---

## 7. 成功标准（可度量）

- **SC-001**: 异动从发生到检测 ≤ 60 秒（一个扫描周期）。
- **SC-002**: 异动从发生到飞书送达端到端 p95 < 60 秒（PRD §7.1）。
- **SC-003**: 持续异动（如持续涨停）不重复推送，**新异动检测准确率 100%**（状态转换无漏报无重报）。
- **SC-004**: 持仓股异动 0 漏报（强制送达）。
- **SC-005**: 数据延迟 > 5 分钟时 100% 暂停扫描，不误报。
- **SC-006**: F1 徽章与 F2 实际异动状态一致性 100%。

---

## 8. 假设（Assumptions）

- F5/F6/F3/F1 均已交付，各自接口可用。
- 行情数据源 60 秒级刷新可支撑分钟级异动检测（Tick 级不做）。
- 自选 ≤30 只，单周期扫描可在数秒内完成。
- 板块整体异动不在 MVP（v1.1）。
- 阈值默认值（振幅 8%/量比 3 倍/窗口 60 日）来自 PRD，可配但 MVP 不做规则编辑器。

## Clarifications

> ② clarify 产出，扫 4 类边界（MVP / API / 数据 / 集成），逐条回写。

### Session 2026-05-20

**[MVP 边界]**
- Q：板块整体异动是否 MVP？
  - A：否，v1.1（PRD Out-of-Scope）。MVP 仅个股价格/量能 + 事件。
- Q：异动阈值可配到什么程度？
  - A：默认值可改（振幅/量比/窗口/各板涨跌停%），但**不做规则编辑器**（用户自写表达式）→ v2。已回写 §2.2/§2.3。
- Q：规则开关粒度？
  - A：按"规则类"开关（涨跌停/涵盖/量能/振幅/事件 各一个开关），FR-008。

**[API 边界]**
- Q：F3 解释超时阈值与 F2 行为？
  - A：F2 调 F3 设超时（如 5s，与 F3 SC-001 一致）；超时/失败 → 推裸卡片（FR-011），不阻塞扫描。
- Q：F6 推送失败 F2 是否管？
  - A：**不管**。F2 调 F6.send 即返回；重试/未送达由 F6 负责（F6 spec 已定）。
- Q：行情延迟判定标准？
  - A：行情快照时间戳距当前 > 5 分钟 → 暂停价格规则（FR-009）；事件规则不受此限（无实时性强约束）。

**[数据边界]**
- Q：涨跌停如何精确判定（一字板/ST/科创）？
  - A：按板块类型取阈值（主板±10%/创业科创±20%/ST±5%），价格触及阈值且封单视为涨跌停；MVP 用"涨跌幅达阈值"近似（封单数据 v1.1）。已回写 Edge Cases / FR-004。
- Q：涵盖（突破前 60 日高低）窗口与数据来源？
  - A：用 F1 kline_service 的近 60 日 K 线算高低点；新股不足 60 日按实际天数。
- Q：停牌/退市股？
  - A：无有效行情 → 跳过价格规则（FR-012）；事件规则仍可匹配其公告。

**[集成边界]**
- Q：dedup 到底在 F2 还是 F6？会不会双重去重打架？
  - A：**两层不同职责**：F2 = 状态转换检测（避免持续异动每周期重复 act + 省 F3 调用）；F6 = 发送级 dedup（code+signal 5 分钟，跨调用方兜底）。互补不打架。已回写 §6。
- Q：F1 徽章回填是 F2 推给 F1 还是 F1 拉 F2？
  - A：**F1 拉**（F2 暴露当前 AnomalyState 接口，F1 每 60 秒刷新周期读取）。降低耦合，F2 不需知道 F1 存在。FR-007。
- Q：扫描调度用谁的调度器？
  - A：复用 F6 引入的 APScheduler（plan 细化）；交易时段判定用 F1 trading_calendar。

> 本轮无需用户拍板的阻塞项；板块异动推迟 v1.1、规则编辑器推迟 v2 均为既定前提。
