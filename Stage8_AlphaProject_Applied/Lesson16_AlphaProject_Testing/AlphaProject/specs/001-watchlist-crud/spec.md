# Feature Specification: 自选股管理 CRUD

**Feature ID**: 001-watchlist-crud（对应 PRD F5）
**Created**: 2026-05-20
**Status**: Draft → Clarified（见末尾 Clarifications 章节）
**来源**: `specs/prd.md` §5.1 F5 · §6 F5 · US-05
**上游约束**: `specs/research/06-架构基线决策.md`（架构基线，技术细节留 plan.md）

> 本文档仅描述 **What & Why**，不含任何技术选型（存储引擎、框架、库、表结构均留给 `plan.md`）。

---

## 1. 为什么做这个功能（Why）

自选股清单是整个 A 股盯盘 AI 助手的**数据基座**：Dashboard（F1）要展示它、异动检测（F2）要扫描它、早盘简报（F4）要遍历它。没有一份可靠、可增删、可分组、可标记持仓的自选股清单，其余三个 Must-have 功能都无从谈起。

当前痛点（PRD §2.1）：用户的关注标的分散在 5+ 个 App，缺少一个**单一可信源**来集中管理"我关心哪些股票、哪些是持仓、哪些只是观察"。F5 解决这个"单一可信源"问题。

## 2. 功能边界（What）

### 2.1 In-Scope（F5 本功能必做）

- 新增自选股（按代码或名称搜索后加入）
- 删除自选股
- 修改自选股的分组归属、持仓标记、显示排序
- 自选股清单的本地持久化（崩溃 / 重启不丢）
- 对外提供"读取当前自选股清单（含持仓标记 + 分组）"的能力，供 F1/F2/F4 消费
- 自选股上限、持仓上限、分组上限的约束校验
- 删除操作的短时撤销

### 2.2 Out-of-Scope（F5 不做，留给其他 feature 或后续版本）

- ❌ 行情数据拉取与展示 → F1 Dashboard
- ❌ 异动徽章计算 → F2 异动检测（F1 消费）
- ❌ 自选股的 AI 分析 / 解释 → F3
- ❌ 推送 → F6
- ❌ 自然语言批量加股（"把光伏板块全加进来"）→ v1.1 自然语言选股
- ❌ 多用户 / 多账号自选清单隔离 → 永久 Won't（单用户工具）
- ❌ 自选股云端同步 / 跨设备同步 → 永久 Won't（本地单机）
- ❌ 自选股历史变更审计 / 操作日志回溯 → v1.1

### 2.3 MVP 约束

- 自选股总量上限 **30 只**（PRD 业务规则：防 LLM 推送成本失控、防 Dashboard 信息密度过大）
- 持仓标记上限 **5 只**（PRD 业务规则：持仓推送优先级最高，避免无差别推送）
- 用户自定义分组上限 **5 个**
- 单用户、本地运行，无鉴权

### 2.4 运行环境

- 本地 Mac 常驻运行（PRD §6 / brainstorming 决议）
- 通过本地内网 / Tailscale 访问的 Web 界面发起增删改
- 数据本地持久化，每日备份 1 次（PRD §7.5）
- 无公网暴露、无多租户

## 3. 用户场景与验收（User Scenarios & Testing）

### User Story 1 — 新增自选股（Priority: P1）

作为本人，我希望按代码或名称搜索一只股票并加入自选清单，可选地指定分组和标记为持仓，以便把我关心的标的集中到单一可信源。

**Why this priority**：没有"加股"就没有自选清单，是整个产品的第一块砖。

**Independent Test**：在空清单状态下搜索"贵州茅台"并加入，清单出现该股即验证成功，不依赖任何其他 feature。

**Acceptance Scenarios**：

1. **Given** 当前自选股数 < 30，**When** 用户搜索"600519"或"贵州茅台"并点击加入，**Then** 该股出现在自选清单顶部（或指定分组），并持久化（重启后仍在）。
2. **Given** 当前自选股已有 30 只，**When** 用户尝试加入第 31 只，**Then** 系统拒绝并提示"自选股已达上限 30，请先移除"，清单无变化。
3. **Given** 用户在加入时勾选"持仓"且当前持仓标记 < 5，**When** 提交，**Then** 该股带持仓标记加入。
4. **Given** 当前持仓标记已有 5 只，**When** 用户加入新股并勾选"持仓"，**Then** 系统拒绝持仓标记并提示"持仓标记已达上限 5"，但允许以非持仓身份加入（用户可二次确认）。
5. **Given** 搜索关键词在全市场股票基础信息中无匹配，**When** 用户搜索"不存在的股"，**Then** 提示"未找到该股票，请确认代码或名称"，不加入。
6. **Given** 该股已在自选清单中，**When** 用户重复加入，**Then** 提示"该股已在自选清单"，不产生重复项。

### User Story 2 — 删除自选股（Priority: P1）

作为本人，我希望从清单中移除不再关注的股票，并能在误删后短时间内撤销，以便保持清单与我的实际关注一致。

**Why this priority**：清单要可收敛，删除与新增同等基础。

**Independent Test**：清单中有 1 只股，删除后清单为空；30 秒内点击撤销恢复该股。

**Acceptance Scenarios**：

1. **Given** 清单中存在股票 X，**When** 用户删除 X 并确认，**Then** X 从清单移除并持久化，且该股的异动扫描 / 推送随即停止（集成约束，见 §6）。
2. **Given** 用户刚删除 X（30 秒内），**When** 用户点击"撤销"，**Then** X 恢复到原分组与原持仓标记状态。
3. **Given** 用户删除 X 已超过 30 秒，**When** 撤销入口消失，**Then** 删除成为终态，需重新搜索加入。
4. **Given** 被删除的 X 存在尚未送达的异动推送，**When** 删除生效，**Then** 该股待推送队列被静默清空，不再发出（避免删除后仍收到推送）。

### User Story 3 — 修改分组与持仓标记（Priority: P2）

作为本人，我希望给自选股分组（如"持仓 / 观察 / 行业"）并切换持仓标记、调整显示顺序，以便对不同分组采用不同的推送优先级与查看方式。

**Why this priority**：分组与持仓标记是 F2 推送优先级（持仓优先）的输入，但 F5 可先交付"加 / 删 / 单一默认分组"再补分组管理。

**Independent Test**：把一只观察股切换为持仓、移动到另一分组，重启后状态保留。

**Acceptance Scenarios**：

1. **Given** 股票 X 在"观察"分组且持仓标记关闭，**When** 用户开启持仓标记（当前持仓 < 5），**Then** X 标记为持仓并持久化。
2. **Given** 持仓标记已达 5 只，**When** 用户尝试再标记一只为持仓，**Then** 拒绝并提示上限。
3. **Given** 用户已创建 5 个自定义分组，**When** 用户尝试创建第 6 个，**Then** 拒绝并提示"分组已达上限 5"。
4. **Given** 用户拖动 / 调整 X 的显示顺序，**When** 保存，**Then** 顺序持久化，下次打开保持。

### Edge Cases

- **空清单**：自选股 0 只时，对外读取接口返回空集合，不报错；F1/F2/F4 各自处理空集合（F5 不负责）。
- **持久化损坏**：本地持久化文件损坏 / 缺失时，以空清单启动 + 提示"自选清单加载失败，已从备份恢复 / 已重置"，不崩溃。
- **并发修改**：单用户场景下，同一时刻两个浏览器标签页同时改 → 以最后写入为准（last-write-wins），不做复杂冲突合并。
- **搜索源不可用**：全市场股票基础信息源临时不可用时，已在清单中的股可正常增删改（不依赖搜索源），但"新增"暂不可用并提示"股票检索暂不可用，请稍后再试"。
- **退市 / 停牌股**：已在清单中的股若退市，保留在清单但标灰，允许手动删除（F5 不主动剔除）。

## 4. 功能需求（Functional Requirements）

- **FR-001**: 系统 MUST 支持按股票代码、名称、**拼音首字母**检索全市场 A 股，返回候选列表供用户选择加入。（拼音检索经用户确认纳入 MVP）
- **FR-002**: 系统 MUST 允许用户将检索到的股票加入自选清单，可选指定分组与持仓标记。
- **FR-003**: 系统 MUST 在自选股总数达到 30 只时拒绝新增并给出明确提示。
- **FR-004**: 系统 MUST 在持仓标记达到 5 只时拒绝新增持仓标记并给出明确提示。
- **FR-005**: 系统 MUST 防止同一股票在清单中重复出现。
- **FR-006**: 系统 MUST 允许用户删除自选股，并在删除后 30 秒内提供撤销。
- **FR-007**: 系统 MUST 在删除自选股时，停止该股的异动扫描并清空其待推送队列（与 F2/F6 的集成约束）。
- **FR-008**: 系统 MUST 允许用户修改自选股的分组归属、持仓标记、显示顺序。
- **FR-009**: 系统 MUST 支持用户自定义分组，上限 5 个。
- **FR-010**: 系统 MUST 将自选清单（含分组、持仓标记、顺序）本地持久化，崩溃 / 重启不丢。
- **FR-011**: 系统 MUST 每日对自选清单做 1 次本地备份。
- **FR-012**: 系统 MUST 对外提供"读取当前自选清单（含每只股的代码、名称、分组、持仓标记、顺序）"的能力，供 F1/F2/F4 消费。
- **FR-013**: 系统 MUST 在持久化文件损坏 / 缺失时优雅降级（从备份恢复或重置为空），不崩溃。
- **FR-014**: 系统 SHOULD 在全市场检索源不可用时，仍允许对已有自选股做增删改（仅"新增检索"不可用）。

## 5. 关键实体（Key Entities）

> 仅描述领域概念与属性，不含表结构 / 字段类型（留 plan.md）。

- **自选股条目（WatchlistItem）**：代表一只被关注的股票。属性：股票代码、股票名称、所属分组、是否持仓、显示顺序、加入时间。
- **分组（Group）**：用户自定义的归类标签（如"观察""新能源"）。属性：分组名、显示顺序。约束：≤ 5 个自定义分组。
- **持仓标记（Holding Flag）**：自选股条目上的布尔维度，独立于分组。约束：全局 ≤ 5 只标记为持仓。
- **全市场股票基础信息（StockBasic）**：检索用的只读参考数据（代码 ↔ 名称映射），来源为行情数据源（具体源留 plan.md）。

---

## 6. 集成边界（与现有 / 后续系统的交互假设）

- **被 F1 Dashboard 消费**：F1 通过 FR-012 的读取能力获取自选清单与持仓标记，用于展示与排序。F5 不负责行情拉取。
- **被 F2 异动检测消费**：F2 扫描 F5 提供的清单；F5 删除股票时须通知 F2 停止该股扫描（FR-007）。
- **被 F4 早盘简报消费**：F4 遍历 F5 清单生成"我的自选股"区块。
- **依赖行情数据源**：FR-001 的全市场检索依赖外部行情数据源提供的"代码 ↔ 名称"基础信息（具体数据源见架构基线 06 / plan.md）。
- **本功能不依赖** F3（LLM）、F6（推送通道）。

---

## 7. 成功标准（Success Criteria · 可度量、技术无关）

- **SC-001**: 用户能在 3 次交互内（搜索 → 选择 → 确认）完成一只股票的加入。
- **SC-002**: 自选清单的增 / 删 / 改操作在 500ms 内给出结果反馈（PRD §7.1）。
- **SC-003**: 应用重启后，自选清单（含分组、持仓、顺序）100% 还原，无丢失。
- **SC-004**: 误删后 30 秒内撤销成功率 100%（恢复到删除前状态）。
- **SC-005**: 所有上限约束（30 / 5 / 5）在达到时 100% 拦截，无越界写入。

---

## 8. 假设（Assumptions）

- 单用户本地工具，无需鉴权 / 多租户（PRD 决议）。
- 全市场股票基础信息可从行情数据源获取（架构基线 06 已锁定数据源候选）。
- 用户自选股规模长期 ≤ 30 只，无需分页 / 虚拟滚动等大规模优化。
- "持仓"为用户手动标记，不与真实券商账户对接（不下单，PRD Non-Goal）。
- 撤销窗口固定 30 秒，MVP 不做可配置。

## Clarifications

> ② clarify 步骤产出（见 `spec.md` 同目录无独立文件，澄清直接并入本节并回写对应段落）。
> 扫描 4 类边界：MVP 边界 / API 边界 / 数据边界 / 集成边界。

### Session 2026-05-20

**[MVP 边界]**
- Q：删除撤销（FR-006）是 F5 MVP 必做还是可推迟？
  - A：**MVP 必做**，但实现为最简单的"软删除 + 30 秒内可恢复"，不引入完整操作历史。已回写 §2.3 与 FR-006。
- Q：自定义分组管理（US3）是否 F5 MVP 必做？
  - A：US3 整体降为 **P2**；F5 MVP 至少交付"加 / 删 + 单一默认分组 + 持仓标记"，分组管理可在 F5 内分阶段交付。已回写 US3 优先级。

**[API 边界]（对外读取能力 FR-012）**
- Q：F1/F2/F4 读取自选清单的接口形态？同步全量读取还是增量订阅？
  - A：MVP 提供**同步全量读取**（一次返回完整清单快照），不做增量订阅 / 变更推送。F1 自行轮询刷新。已补入 §6。
- Q：读取接口的数据时效性要求？
  - A：自选清单是本地数据，读取即最新，无延迟约束（区别于行情数据）。

**[数据边界]**
- Q：股票检索的匹配规则（精确 / 前缀 / 模糊 / 拼音）？PRD 未明确。
  - A：**用户已拍板（2026-05-20）**：MVP 即支持代码精确 + 前缀匹配、名称包含匹配、**拼音首字母检索**。已回写 FR-001（拼音纳入 MVP），plan.md 增加拼音转换依赖，tasks T005 含拼音匹配。
- Q：持久化损坏时的恢复策略？
  - A：优先从每日备份恢复；备份也不可用则重置为空清单 + 提示。已补入 FR-013 与 Edge Cases。
- Q：退市 / 停牌股如何处理？
  - A：保留标灰、允许手动删除，F5 不主动剔除。已补入 Edge Cases。

**[集成边界]**
- Q：删除股票时如何确保 F2 停止扫描、F6 不再推送该股？
  - A：F5 删除时**主动通知**异动扫描组件停止该股 + 清空其待推送队列（FR-007）。具体通知机制（事件 / 直接调用）留 plan.md。
- Q：全市场检索源不可用时，增删改是否受影响？
  - A：仅"新增检索"不可用；已有自选股的删 / 改不受影响（FR-014）。已补入 Edge Cases。

> 本轮澄清 1 个默认假设经用户拍板修正：**拼音检索纳入 MVP**（非推迟 v1.1）。US3 分组管理经用户确认降为 P2。其余假设维持。
