## 2. 项目背景与目标

### 2.1 背景

本人在 A 股市场处于「混合操作 + 学习探索」阶段（日内 / 波段 / 价投都偶尔做，仍在收敛风格），核心日常痛点：

1. **多次切换 App 看盘**：自选股动态分散在同花顺 / 东方财富 / 雪球 / 财联社 / 公众号 5+ 个入口，单日切换耗时占用大量注意力
2. **怕错过关键信号**：持仓股突变 / 自选股突破 / 板块异动 / 重大公告 4 类信号靠人工监控不可靠，盘中常常事后才知道发生了什么
3. **早盘信息漏看**：盘前 9:00-9:25 关键时间窗，信息密度极高（隔夜外盘 / 财联社昨夜要闻 / 关注股研报），靠手翻公众号低效
4. **缺少「为什么」的认知反馈**：看到自选股涨停只看到结果，难以快速理解「为什么涨」「跟什么产业链相关」「哪条政策驱动的」，认知形成速度慢

业内主流盯盘 App（同花顺 / 东方财富 / 雪球 / 富途 / 选股宝 / 韭研公社）功能强但形态保守，**没有一个把"AI 解释型推送 + 学习型反馈"作为核心产品价值**；AI 涨乐 / 妙想 / 问财 等 AI 产品则面向大众散户，与本人「个人学习」场景不匹配。

### 2.2 目标

**业务目标**（个人内在动机）：
- 用 AI 助手将"切换 App + 错过异动 + 早盘信息漏看 + 缺少认知反馈"的时间损失降到最低
- 通过 AI 解释型推送加速对市场认知的形成（学习目标 = 用 6 个月把"看不懂的异动" 比例从今天 80% 降到 30% 以下）

**产品目标**（产品要做到什么）：
- **单一界面**承载日常盯盘 90% 工作量，消灭多 App 切换
- **盘中 60 秒内**主动推送 4 类关键异动（持仓 / 自选 / 板块 / 事件），每次推送附 ≤200 字 AI 解释
- **盘前 9:15 自动**收到含市场概览 + 自选观察清单 + 财联社昨夜要闻的早盘简报
- **MVP 6 周内**可用，月运行成本 ≤ 100 元

**学习目标**（探索性项目假设验证）：
- 假设 A：AI 解释型推送相对纯阈值推送，能更快帮助散户形成认知（用"6 个月后自评看懂率"度量）
- 假设 B：本地 Mac 常驻 + 飞书推送的形态在工程上可持续，不会因为运维负担放弃

### 2.3 非目标（Non-Goals · 明确不做）

- ❌ **不做下单 / 交易执行** —— 未持牌、避免监管擦边，最多到"加入自选 + 推送 + 跳转券商 App"
- ❌ **不对外开放 / 不收费 / 不做 SaaS** —— 单用户本地工具，永远不接受外部用户注册
- ❌ **不做 Tick / Level-2 实时行情** —— 学习探索阶段，分钟级延迟可接受；MiniQMT 等 10 万门槛通道暂不引入
- ❌ **不做港美股 / 加密货币 / 期货** —— MVP 只覆盖 A 股
- ❌ **不做社区 / UGC / 跟单 / 模拟盘** —— 个人工具不引入社交
- ❌ **不做视频 / 音频简报** —— 文字版飞书卡片信息密度更高
- ❌ **不做回测引擎 / 因子库 / 量化策略托管** —— 学习探索阶段不需要，留作 v2 Could-have
- ❌ **不做微信公众号 / 服务号推送** —— 个人号 API 限制大，飞书机器人已足够
- ❌ **不做 macOS / iOS 原生 App** —— Web Dashboard + 飞书 + 浏览器够用

### 2.4 战略对齐

- 个人项目，无组织 OKR
- 同时作为 **AI 编程辅助 + Vibe Coding 工作流验证项目**（具体不在本 PRD 范围）

## 4. 用户故事 / 使用场景

### US-01 一屏看完自选股
**作为** 本人，
**我希望** 在 Web Dashboard 上 60 秒内看到全部自选股最新报价 + 涨跌幅 + 异动徽章，
**以便** 我不需要在 5 个 App 之间来回切换。

- **触发情境**：每个交易日开盘前 5 分钟 + 盘中 3-4 次主动刷新
- **期望结果**：用户对自己"所有关心的股票今天表现"在 30 秒内建立心理快照

### US-02 关键异动 60 秒推送
**作为** 本人，
**我希望** 持仓股 / 自选股发生关键异动（涵盖突破、破位、量能异常、涨跌停）时，60 秒内收到飞书卡片推送，
**以便** 我即使不在屏幕前也不错过决策时机。

- **触发情境**：盘中 9:30-15:00，本人在做其他事（写代码 / 开会 / 通勤）
- **期望结果**：被推送提醒回到 Dashboard 决定是否动手；或仅作为信息记录留底

### US-03 早盘简报盘前必达
**作为** 本人，
**我希望** 每个工作日 9:15 自动收到飞书早盘简报（含市场概览 + 我的自选股观察清单 + 财联社昨夜要闻），
**以便** 我用 5 分钟刷完所有早盘关键信息。

- **触发情境**：早上 9:00-9:15 通勤 / 起床期间
- **期望结果**：用户在 9:25 集合竞价前对当日市场风向有判断

### US-04 AI 解释型推送加速认知
**作为** 本人，
**我希望** 异动推送卡片附 ≤200 字 LLM 解释（为什么涨 / 跌、产业链关联、相关研报或政策），
**以便** 我把"看到涨停"转化为"理解涨停逻辑"，加速认知形成。

- **触发情境**：US-02 推送到达后展开
- **期望结果**：用户每收 10 条推送积累 5-8 条新认知（行业 / 公司 / 政策 / 板块）

### US-05 自选股管理 + 持仓标记
**作为** 本人，
**我希望** 在 Dashboard 增删自选股、按"持仓 / 观察 / 行业"标记分组，
**以便** 我能对不同分组采用不同的推送优先级（持仓推送优先级最高）。

- **触发情境**：每周整理一次自选清单，盘中临时加股
- **期望结果**：自选 ≤ 30 只总量上限内，能保持清单与本人实际关注一致

## 6. 详细功能描述

### F1 自选股 Dashboard

**触发**：用户在浏览器打开 Web Dashboard URL（本地 Mac 自建，通过 Tailscale / 本地内网访问）

**输入**：
- 无显式输入（隐式：用户当前自选股清单、当前交易时段、本人持仓标记状态）

**核心流程**：
1. 读取本地存储的自选股清单（≤ 30 只）+ 持仓标记 + 分组
2. 并发拉取每只股票最新报价快照（来自分钟级数据源，60s 刷新一次）
3. 应用异动规则引擎，给每只股票打上异动徽章（涨跌停 / 涵盖 / 量能 / 突破前 N 日高低）
4. 按"持仓优先 → 异动优先 → 字母序"排序展示
5. 支持手动刷新 + 自动 60s 刷新 + 点击单股进入详情页

**输出**：
- 自选股列表，每项含：代码 / 名称 / 最新价 / 涨跌幅 / 量比 / 异动徽章 / 持仓标记 / 所属分组
- 顶部市场概览栏：上证 / 深证 / 创业板指数实时
- 异动徽章颜色编码：红=涨停 / 绿=跌停 / 橙=涵盖 / 蓝=突破 / 黄=量能异常

**边界条件**：
- 数据源（AkShare 类）超时 / 返空 → 显示上一次成功拉取值 + 时间戳 + "N 秒前数据"标记，不弹错
- 单股数据缺失（如新股次新停牌）→ 该项灰显 + 不参与排序，不阻塞整体渲染
- 自选股 0 只 → 显示空状态引导"先添加你的第一只自选股"
- 交易日历判定：非交易时段（夜间 / 周末 / 节假日）→ Dashboard 顶部显示"非交易时段，数据为最后收盘价"
- 用户网络不通 → 显示离线提示 + 自动重试机制

**异常处理**：
- 数据源全部失败超过 5 分钟 → 顶部红色 banner 提示 + 写日志，不阻塞 Dashboard 渲染
- 用户加股票超 30 只 → 提示"自选股上限 30，请先移除 X 只"

**性能要求**：详见 §7 NFR

**业务规则**：
- 自选股上限 = 30 只（防 LLM 推送成本失控、防 Dashboard 信息密度过大）
- 持仓标记限 ≤ 5 只（持仓推送优先级最高，避免无差别推送）
- 分组限 ≤ 5 个

### F2 异动检测与推送

**触发**：盘中（9:30-11:30 / 13:00-15:00）每 60 秒一次定时扫描；事件源（财联社 / 公告）实时推送回调

**输入**：
- 全部自选股最新行情快照（分钟级）
- 财联社电报 / 上交所 / 深交所公告流（事件源）

**核心流程**：
1. **价格 / 量能规则引擎**（针对自选股每分钟扫描）：
   - 涨停 / 跌停（含 ST 板 ±5% 边界判定）
   - 涵盖：突破前 60 日新高 / 跌破前 60 日新低
   - 量能异常：量比 > 5 日均量 × 3 倍
   - 振幅异常：日内振幅 > 8%
2. **事件规则引擎**（针对自选股关键词匹配 + 公告流）：
   - 关键事件：业绩 / 分红 / 重组 / 减持 / 监管处罚 / 重大合同
   - 财联社电报红色 / 紧急标签匹配自选股代码或公司名
3. **dedup**：同股票 + 同信号在 5 分钟内只推送一次
4. **优先级队列**：持仓股 > 自选股 > （板块异动 v1.1）
5. 命中规则 → 入推送队列 → 调用 F3 LLM 解释 → 渲染飞书卡片 → F6 推送通道发送

**输出**：
- 飞书卡片：股票名 + 代码 + 当前价 + 涨跌幅 + 异动类型 + AI 解释 + 时间戳 + 跳转 Dashboard 链接

**边界条件**：
- LLM 解释生成失败（API 失败 / 超时）→ 推送基础信息卡片（无 AI 解释），日志记录 LLM 失败
- 推送通道（飞书 webhook）失败 → 重试 3 次（间隔 30 秒）→ 仍失败则记录到本地"未送达队列"，Dashboard 顶部显示"N 条推送未送达"
- 单分钟内同股触发多个规则 → 合并为一张卡片，多个徽章
- 单批次异动 > 10 只 → 合并为一张"批量异动"卡片（避免推送轰炸）
- 数据源延迟 > 5 分钟 → 暂停规则引擎扫描 + Dashboard 警示，避免基于过期数据误报

**异常处理**：
- 推送频率超阈值（单分钟 > 20 条）→ 自动转为"批量摘要"模式 + Dashboard 通知

**性能要求**：详见 §7 NFR

**业务规则**：
- 持仓股异动 → 强制推送，不受 dedup 影响（持仓优先级最高）
- 非交易时段不扫描价格规则，但事件规则（公告 / 财联社）持续扫描
- 用户可在设置中关闭某一类异动（如关闭"量能异常"）

### F3 LLM 异动解释

**触发**：F2 命中规则后自动调用，或用户在 Dashboard 点击单股"为什么"按钮

**输入**：
- 股票代码 + 名称 + 异动类型（涨停 / 涵盖 / 等）+ 当前价格 + 涨跌幅 + 量比
- 上下文：今日板块涨幅、行业归属、近 7 日财联社相关电报、近 30 日重大公告

**核心流程**：
1. 组装结构化 prompt（含异动事实 + 上下文 + 输出格式约束 200 字）
2. 调用主 LLM（DeepSeek / Qwen 二选一，可降级）生成解释
3. 输出格式约束：
   - 第 1 句：异动直接原因（如"受光伏政策催化"）
   - 第 2 句：产业链 / 公司基本面关联
   - 第 3 句（可选）：相关研报 / 政策链接
4. 失败降级：主 LLM 超时 → 备 LLM；备也超时 → 跳过 LLM 解释，发裸卡片

**输出**：
- ≤ 200 字 Markdown 文本，不含买卖建议性词汇（"建议买入" / "强烈推荐" 禁用）

**边界条件**：
- LLM 输出 > 200 字 → 截断 + 加 "..." 后缀
- LLM 输出含敏感词（买卖建议 / 价格预测）→ 替换为中性表达 或 标记需人工 review
- LLM 输出 0 字 / 返回失败 → 降级到模板式描述（"X 涨幅 X%，触发规则 X"）
- 上下文数据缺失（如新闻拉取失败）→ 仅基于行情数据生成，附"信息不全"标签

**异常处理**：
- 单日 LLM 调用预算（默认 200 元）耗尽 → 自动切换到本地小模型（如 Ollama 上的 Qwen 7B）或纯模板模式

**性能要求**：详见 §7 NFR

**业务规则**：
- 必须附风险提示尾标"以上为信息整理，不构成投资建议"（合规自律）
- 同股 5 分钟内重复异动复用上次解释结果（缓存命中）

---

### F4 早盘简报

**触发**：工作日 09:15:00 ±30 秒（节假日 / 周末跳过）

**输入**：
- 隔夜外盘指数（美三大 / 欧三大 / 港股夜盘）
- 昨日 A 股收盘行情 + 板块涨跌幅
- 财联社昨夜 19:00-09:00 电报（红色 / 紧急 / 涉及自选股关键词）
- 用户当前自选股清单 + 持仓标记
- 今日重要日历事件（财报披露 / 经济数据公布）

**核心流程**：
1. 定时器触发（基于本地 cron / 应用层调度器，含交易日历判定）
2. 并发拉取 5 类数据
3. 组装结构化 prompt → LLM 生成简报正文（≤ 1200 字）
4. 渲染飞书 Markdown 卡片（分 4 区块：市场 / 自选 / 财联社 / 日历）
5. 通过 F6 推送

**输出**：
- 飞书 Markdown 卡片，4 区块：
  1. **市场概览**（隔夜外盘 + 昨收 + 今日预期）
  2. **我的自选股**（按持仓 / 异动优先级排序，每股一行 + 一句 AI 评论）
  3. **财联社昨夜要闻**（≤ 5 条，挑选与自选股关联或市场级重要）
  4. **今日日历**（财报 / 数据 / 监管会议）

**边界条件**：
- 9:15 前任一数据源失败 → 跳过该区块，简报仍按时发出（不阻塞整体）
- 自选股 0 只 → 跳过"我的自选股"区块
- 节假日 / 周末 → 不发送
- 9:14:59 仍未生成完 → 发"预热版"简报（只含已就绪区块），9:18 补发完整版

**异常处理**：
- LLM 生成超时（> 60 秒）→ 发裸数据版（无 AI 评论）
- 飞书推送失败 → 重试 3 次 + 记录到 Dashboard 内"今日简报历史"页

**性能要求**：详见 §7 NFR

**业务规则**：
- 简报必须附风险提示尾标
- 简报 9:30 后用户可在 Dashboard 内回看（保留 30 天）

### F5 自选股管理 CRUD

**触发**：用户在 Dashboard 增 / 删 / 改自选股

**输入**：
- 增：股票代码或名称（支持模糊搜索）+ 可选分组 + 可选"持仓"标记
- 删：股票代码
- 改：分组 / 持仓标记 / 排序

**核心流程**：
1. 增：搜索匹配 → 用户确认 → 检查 30 只上限 / 持仓 5 只上限 → 写本地存储 → 重渲染 Dashboard
2. 删：用户确认 → 移除存储 → 立即停止该股的异动扫描和推送
3. 改：分组下拉 + 持仓 toggle → 写存储

**输出**：
- 操作成功 / 失败提示
- Dashboard 自动刷新

**边界条件**：
- 搜索关键词无匹配 → 提示"未找到该股票，请确认代码或名称"
- 增到第 31 只 → 阻止 + 提示"自选股上限 30"
- 增持仓到第 6 只 → 阻止 + 提示"持仓标记上限 5"
- 删除时该股有未推送的异动 → 静默清空队列，不发推送

**性能要求**：详见 §7 NFR

**业务规则**：
- 自选数据本地持久化，崩溃 / 重启不丢
- 删除操作可撤销（30 秒内）

### F6 飞书机器人推送通道

**触发**：F2 / F3 / F4 任一推送需求

**输入**：
- 推送类型（异动 / 简报 / 系统通知）
- 卡片内容（Markdown 或结构化 card JSON）
- 优先级（持仓 / 自选 / 系统）

**核心流程**：
1. 令牌桶限频（飞书 100/min 上限，应用层留 30% 余量 = 70/min）
2. dedup（与 F2 dedup 协同，5 分钟同股同信号不重发）
3. 渲染卡片（Markdown / interactive card）+ 签名校验
4. POST 到飞书 webhook URL
5. 重试机制：失败 → 30s 后重试 → 90s 再重试 → 仍失败则入"未送达队列"

**输出**：
- 飞书消息送达
- 推送日志（送达 / 失败 / 重试次数）

**边界条件**：
- 单分钟超 70 次 → 自动合并卡片（一张卡 10 股）
- 飞书 webhook URL 失效 → Dashboard 红色警示 + 暂停所有推送 + 等用户在设置里更新 URL
- 推送内容含飞书禁用词 → 自动换词 + 日志记录

**性能要求**：详见 §7 NFR

**业务规则**：
- 持仓股推送绕过 dedup（强制送达）
- 用户可在设置中"全局静音"（如周末 / 出差期间）

## 7. 非功能需求（NFR）

### 7.1 性能

- **Dashboard 首屏加载** p95 < 2 秒（本地局域网访问）
- **Dashboard 数据刷新** 60 秒间隔（与上游 AkShare 类分钟数据节拍一致）
- **异动推送延迟** p95 < 60 秒（从异动发生到飞书消息送达）
- **早盘简报送达** 09:15:00 ± 30 秒（节假日 / 周末跳过）
- **LLM 异动解释生成** p95 < 5 秒（含失败重试）
- **自选股 CRUD 响应** p95 < 500ms（本地存储）

### 7.2 可用性

- 交易时段（工作日 09:15-15:00）可用性 ≥ 99%（个人工具，单机不追求 SLA）
- 故障恢复 RTO < 5 分钟（手动重启 docker-compose），RPO < 1 小时（本地数据备份频率）
- Mac 防睡眠：交易时段强制不睡（系统级 caffeinate 等机制）
- Mac 关机 / 网络中断 → 重启后回放当日错过的异动（最多回放 200 条，过多则汇总）

### 7.3 安全

- 飞书 webhook URL + LLM API Key + Tushare Token **本地加密存储**（不入 git）
- 不存储任何身份证 / 银行卡 / 真实下单凭证（本产品不接触交易）
- Dashboard 通过 Tailscale / 本地内网访问（不公网暴露）
- 推送内容不含个人 PII

### 7.4 合规

- **所有 AI 生成内容附风险提示尾标**："以上为信息整理，不构成投资建议"
- **禁止生成买卖建议性词汇**（"建议买入" / "强烈推荐" / "目标价" 等）→ 后处理自动替换或拦截
- **数据源使用合规**：
  - Tushare Pro：协议非商业化，本产品个人非商用 ✓
  - AkShare：MIT，数据继承上游 ToS，**个人非商用** ✓
  - 财联社电报：仅做信息浏览，不二次分发
- **不持牌不下单**：永久 Non-Goal

### 7.5 数据

- 自选股清单 / 推送日志本地备份，每日 1 次
- 历史行情 / 财务数据按需拉取 + 本地缓存，无强制保留期限
- 推送日志保留 ≥ 90 天（用于复盘）

### 7.6 可访问性

- 单用户工具，A11y 不强制
- 支持桌面 + 移动浏览器响应式（基本可读即可）

### 7.7 国际化

- 仅简体中文
- 字符编码 UTF-8

### 7.8 成本

- 月运行成本 ≤ 100 元
  - LLM API：~50-80 元（DeepSeek / Qwen，按日均 20-30 条推送 + 简报估算）
  - Tushare Pro 5000 积分（可选）：500 元 / 年 ≈ 42 元 / 月
  - 服务器：0 元（本地 Mac）
- 单日 LLM 调用预算：≤ 5 元（约 500 次调用）

## 9. 验收标准

### AC-F1-01：Dashboard 首屏 ≤ 2 秒
**Given** 用户已设置 5 只自选股 + 后端服务正常运行
**When** 用户在浏览器打开 Dashboard URL
**Then** 首屏（含全部 5 只报价 + 异动徽章）在 2 秒内完整渲染

### AC-F1-02：自选股达到 30 只上限
**Given** 用户已有 30 只自选股
**When** 用户尝试添加第 31 只
**Then** 系统拒绝 + 提示"自选股上限 30，请先移除"，原列表无变化

### AC-F1-03：数据源失败优雅降级
**Given** 上游数据源（AkShare 类）持续返回错误超过 1 分钟
**When** Dashboard 自动刷新触发
**Then** Dashboard 显示上一次成功值 + "N 秒前数据"标记，顶部黄色 banner 提示，不弹错不崩溃

### AC-F2-01：异动推送 ≤ 60 秒
**Given** 用户持仓股 X 触发"涨停"规则
**When** 涨停发生
**Then** 60 秒内飞书收到含股票名 + 价格 + 异动类型 + AI 解释的卡片

### AC-F2-02：dedup 同股 5 分钟不重推
**Given** 用户自选股 Y 在 14:00 触发"量能异常"推送
**When** 14:03 该股再次触发"量能异常"
**Then** 不重复推送（5 分钟 dedup），但若 14:03 同时触发"突破"（新信号），则推送"突破"

### AC-F2-03：持仓股绕过 dedup
**Given** 用户持仓股 Z 在 14:00 触发"量能异常"推送
**When** 14:03 同股再次触发"量能异常"
**Then** 仍推送（持仓优先级最高，绕过 dedup）

### AC-F3-01：LLM 解释 ≤ 200 字 + 含尾标
**Given** F2 触发推送
**When** F3 生成 AI 解释
**Then** 解释正文 ≤ 200 字 + 必含"以上为信息整理，不构成投资建议"尾标 + 不含买卖建议性词汇

### AC-F3-02：LLM 失败降级
**Given** 主 LLM API 超时 5 秒
**When** F3 调用
**Then** 自动切备用 LLM；备用也超时则发不含 AI 解释的裸卡片，日志记录失败

### AC-F4-01：早盘简报准时
**Given** 当前是工作日 09:15:00
**When** 时钟到点
**Then** ±30 秒内飞书收到 Markdown 卡片，含市场 / 自选 / 财联社 / 日历 4 区块

### AC-F4-02：简报降级
**Given** 09:14:50 财联社数据源未就绪
**When** 09:15:00 触发简报
**Then** 简报按时发出 + 财联社区块显示"数据获取中"，09:18 自动补发完整版

### AC-F4-03：节假日不发简报
**Given** 当前是周六 / 法定节假日
**When** 09:15:00 时钟到点
**Then** 不发简报，日志记录"非交易日，跳过"

### AC-F5-01：自选股 CRUD
**Given** 用户有 10 只自选股
**When** 用户添加贵州茅台（600519）
**Then** 列表变为 11 只，新股 1 秒内出现在 Dashboard

### AC-F6-01：飞书推送限频
**Given** 单分钟内 25 条异动需推送
**When** F6 触发推送
**Then** 自动合并为合并卡片（最多 10 股 / 卡），不超过飞书 70/min 限频

### AC-NFR-01：成本守门
**Given** 单日 LLM 调用累计成本接近预算上限（4.5 元 / 5 元日预算）
**When** 第 N+1 次推送触发 LLM 调用
**Then** 自动切本地小模型 或 跳过 LLM；Dashboard 顶部黄色 banner 提示

## 11. 度量指标

### 11.1 北极星指标

**"日均盯盘 AI 助手使用时长 ≥ 我使用其他看盘 App 的时长"**

度量方式：自评（每周日记录），目标 8 周后达成。

### 11.2 关键指标（个人版 AARRR 简化）

**Activation（激活）**：
- MVP 上线后 7 日内：自选股数 ≥ 10、首条飞书推送送达、首份早盘简报送达 → 三件齐全

**Retention（留存）**：
- 连续 30 天交易日：日均使用 Dashboard ≥ 1 次 + 接收飞书推送 ≥ 5 条
- 连续 60 天交易日：不停机 / 不弃用

**Quality / Depth（深度使用）**：
- 异动推送的"点击查看 AI 解释"率 ≥ 40%
- 早盘简报"完整阅读"率 ≥ 80%（自评）

**Cognition（认知形成 · 学习目标）**：
- 6 个月后自评"看到自选股异动能 30 秒内说清涨跌原因"比例从 20% → 70%+

### 11.3 反指标（防止"指标作弊"）

- **推送条数 / 天 ≤ 50**（防止规则过激刷量，影响阅读体验）
- **dedup 命中率 ≥ 30%**（防止规则太松导致重复推送）
- **LLM 解释失败率 ≤ 5%**（防止降级到裸卡片太频繁，影响 AI 价值）
- **月成本 ≤ 100 元**（防止 LLM 调用失控）

### 11.4 度量频率

- **每日**：推送条数 / LLM 成本 / 系统停机时长
- **每周**：自评学习 / 使用时长
- **每月**：北极星 + 留存 + 反指标全量

### 11.5 关停线

任一条触发即关停 / 重构：

- 连续 4 周交易日 < 1 次 / 周使用 Dashboard
- 连续 2 周收到 0 次推送（说明规则没用 或 系统挂了不修）
- 月成本 > 200 元 连续 2 月（说明 LLM 失控）
- 6 个月学习目标未见提升（自评看懂率没动）
