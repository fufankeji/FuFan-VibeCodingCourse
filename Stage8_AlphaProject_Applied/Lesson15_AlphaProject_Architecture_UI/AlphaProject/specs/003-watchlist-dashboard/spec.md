## 1. 为什么做这个功能（Why）

PRD §2.1 第 1 痛点：自选股动态分散在 5+ 个 App，单日反复切换耗费大量注意力。F1 是产品对这个痛点的**正面回答** —— 一个单一界面（开屏即见）让用户 60 秒内看完所有关心的股票今天表现，消灭多 App 切换。

它也是产品**最早可见价值**的载体：只依赖 F5（自选清单）+ 行情数据源即可独立交付，不必等异动检测 / AI 解释 / 推送链路成型。

---

## 2. 功能边界（What）

### 2.1 In-Scope（F1 报价优先版必做）

- Web 单页 Dashboard，开屏即展示自选股清单
- 读取 F5 自选清单（含分组、持仓标记、顺序）
- 并发拉取每只自选股的最新报价快照，60 秒自动刷新 + 手动刷新
- 列表展示：代码 / 名称 / 最新价 / 涨跌幅 / 量比 / 持仓标记 / 所属分组
- 顶部市场概览栏：上证 / 深证 / 创业板指数实时
- 排序：持仓优先 → 涨跌幅 → 字母序（**异动优先排序待 F2 徽章落地后补**）
- 分组筛选 / 切换
- 单股详情页：实时 K 线 + 基础行情
- 数据源失败 / 超时 / 空值的优雅降级展示
- 空状态（0 只自选股）引导
- 交易时段判定（非交易时段标记"收盘价"）
- 顶部展示推送状态（消费 F6 的未送达数 / 连接状态 / 静音态，F6 未就绪时降级隐藏）

### 2.2 Out-of-Scope（F1 不做 / 推迟）

- ❌ **异动徽章计算与展示** → 依赖 F2 规则引擎，**方案 A 推迟**，F2（005）落地后作为 F1 增量补充
- ❌ **异动优先排序** → 同上，依赖徽章
- ❌ **AI 解释展开** → F3（004）
- ❌ **自选股增删改 CRUD 逻辑** → F5（001）负责；F1 只读展示 + 提供跳转到 F5 管理界面的入口
- ❌ **板块 / 行业热力图** → v1.1（PRD Out-of-Scope）
- ❌ **涨跌榜 / EOD 筛选 / Scanner** → SD 自带页面，但非 F1 MVP，v1.1 再启用
- ❌ **推送本身** → F6（002）
- ❌ **历史行情回放 / 复盘** → v1.1

### 2.3 MVP 约束

- 自选股 ≤ 30 只（PRD 业务规则，无需分页 / 虚拟滚动）
- 报价刷新间隔 60 秒（与分钟级数据源节拍一致，PRD §7.1）
- 单用户本地，无鉴权
- 报价优先版：先上报价 + 市场概览 + 排序 + 详情页，异动徽章留接口位

### 2.4 运行环境

- 后端跑在本地 Mac，前端经 Tailscale / 本地内网用浏览器访问（桌面 + 移动响应式）
- 行情快照来自外部行情数据源（具体源见架构基线 06 / plan.md）
- 复用 F5 的自选清单读取能力

## 3. 用户场景与验收

### User Story 1 — 一屏看完自选股报价（Priority: P1）🎯 MVP

作为本人，我希望打开 Dashboard 就在 60 秒内看到全部自选股的最新价与涨跌幅，按持仓优先排列，以便我不再切换 5 个 App。

**Why this priority**：这是 F1 的核心价值，消灭多 App 切换的直接兑现。

**Independent Test**：F5 中已有 5 只自选股（含 1 只持仓），打开 Dashboard → 5 只全部显示报价、涨跌幅，持仓股置顶，即验证成功（不依赖 F2/F3/F6）。

**Acceptance Scenarios**：

1. **Given** F5 中有 5 只自选股（1 只标记持仓），**When** 用户打开 Dashboard，**Then** 60 秒内 5 只全部显示代码/名称/最新价/涨跌幅/量比，持仓股排在最前。
2. **Given** Dashboard 已打开，**When** 经过 60 秒，**Then** 报价自动刷新为最新快照，无需手动操作；用户也可点"刷新"立即更新。
3. **Given** 自选清单为空（0 只），**When** 打开 Dashboard，**Then** 显示空状态引导"先去添加你的第一只自选股"+ 跳转 F5 管理入口。
4. **Given** 某只股票数据源返回空 / 停牌，**When** 渲染列表，**Then** 该项灰显标"停牌 / 无数据"，不参与排序，不阻塞其他股票展示。

### User Story 2 — 市场概览（Priority: P1）🎯 MVP

作为本人，我希望 Dashboard 顶部常驻上证 / 深证 / 创业板指数，以便我一眼判断大盘环境。

**Acceptance Scenarios**：

1. **Given** Dashboard 打开且在交易时段，**When** 页面加载，**Then** 顶部显示上证/深证/创业板指数最新点位与涨跌幅，随报价同步 60 秒刷新。
2. **Given** 当前为非交易时段（夜间/周末/节假日），**When** 打开 Dashboard，**Then** 指数与个股均标"非交易时段，数据为最后收盘价"。

### User Story 3 — 单股详情 + K 线（Priority: P2）

作为本人，我希望点击单只股票进入详情页看实时 K 线，以便快速判断走势。

**Acceptance Scenarios**：

1. **Given** Dashboard 列表中有股票 X，**When** 用户点击 X，**Then** 进入详情页显示 X 的实时 K 线 + 基础行情（开/高/低/收/量）。
2. **Given** 详情页 K 线数据拉取失败，**When** 渲染，**Then** 显示"K 线加载失败，请重试"，不崩溃，基础行情仍展示。

### User Story 4 — 推送状态条（Priority: P2，依赖 F6）

作为本人，我希望 Dashboard 顶部显示飞书推送的健康状态（未送达数 / 连接 / 静音），以便我知道推送是否正常。

**Acceptance Scenarios**：

1. **Given** F6 推送通道存在未送达消息，**When** Dashboard 加载，**Then** 顶部显示"N 条推送未送达"。
2. **Given** F6 尚未就绪（002 未实现），**When** Dashboard 加载，**Then** 推送状态条降级隐藏，不报错。

### Edge Cases

- **行情源全部失败 > 5 分钟**：顶部红色 banner 提示"行情数据获取异常"+ 写日志，列表仍显示上次成功值 + "N 秒前数据"标记，不阻塞渲染。
- **行情源单次超时 / 返空**：显示上一次成功拉取值 + 时间戳，不弹错。
- **自选股新加入但行情未就绪**：该项显示"加载中"，下一刷新周期补上。
- **用户网络不通**（前端连不上本地后端）：前端显示离线提示 + 自动重试。
- **退市股**：行情源无数据 → 灰显 + 提示"已退市/无行情"，引导去 F5 删除。
- **移动端窄屏**：列表自适应为紧凑卡片，关键字段（名称/价/涨跌幅）优先。

## 4. 功能需求（Functional Requirements）

- **FR-001**: 系统 MUST 读取 F5 自选清单（含分组、持仓标记、顺序）作为 Dashboard 数据源。
- **FR-002**: 系统 MUST 并发拉取每只自选股最新报价快照（最新价、涨跌幅、量比）。
- **FR-003**: 系统 MUST 每 60 秒自动刷新报价，并提供手动刷新。
- **FR-004**: 系统 MUST 在顶部展示上证 / 深证 / 创业板指数实时点位与涨跌幅。
- **FR-005**: 系统 MUST 按"持仓优先 → 涨跌幅 → 字母序"排序展示（异动优先待 F2）。
- **FR-006**: 系统 MUST 支持按分组筛选 / 切换。
- **FR-007**: 系统 MUST 提供单股详情页，展示实时 K 线 + 基础行情。
- **FR-008**: 系统 MUST 在行情源超时 / 返空时显示上次成功值 + 时间戳，不弹错不崩溃。
- **FR-009**: 系统 MUST 在行情源持续失败 > 5 分钟时给出顶部告警 banner。
- **FR-010**: 系统 MUST 在自选清单为空时显示空状态引导 + 跳转 F5 管理入口。
- **FR-011**: 系统 MUST 判定交易时段，非交易时段标记"收盘价"。
- **FR-012**: 系统 MUST 对停牌 / 退市 / 无数据股票灰显且不参与排序。
- **FR-013**: 系统 MUST 支持桌面 + 移动浏览器响应式展示。
- **FR-014**: 系统 SHOULD 消费 F6 推送状态（未送达数 / 连接 / 静音）并在顶部展示；F6 未就绪时降级隐藏。
- **FR-015**: 系统 MUST 预留异动徽章展示位（数据来自 F2），F2 未就绪时不展示徽章（方案 A）。

## 5. 关键实体（Key Entities）

- **报价快照（QuoteSnapshot）**：单只股票某时刻行情。属性：代码、最新价、涨跌幅、量比、成交量、更新时间、数据状态（正常/停牌/无数据/陈旧）。
- **市场指数（MarketIndex）**：大盘指数。属性：指数名（上证/深证/创业板）、点位、涨跌幅、更新时间。
- **Dashboard 展示项（DashboardRow）**：列表一行的聚合视图 = F5 的 WatchlistItem（代码/名称/分组/持仓/顺序）+ QuoteSnapshot（行情）+ 异动徽章位（F2，暂空）。
- **K 线数据点（KlinePoint）**：详情页用。属性：时间、开/高/低/收、成交量。

---

## 6. 集成边界

- **依赖 F5（001）**：通过 F5 的全量读取接口（FR-012 of 001）获取自选清单 + 持仓标记 + 分组。F1 只读，不做 CRUD（增删改跳转 F5 管理界面）。
- **依赖行情数据源**：报价快照 + 指数 + K 线来自外部行情源（AkShare 类，具体见 plan.md）。
- **可选消费 F6（002）**：读 F6 的 push_status 展示推送健康状态；F6 未就绪降级隐藏（FR-014）。
- **预留 F2（005）接口**：异动徽章数据由 F2 提供，F1 预留展示位（FR-015），F2 落地后补。
- **复用前端基线**：fork SD（chengzuopeng/stock-dashboard）的 Dashboard / 详情页骨架。

---

## 7. 成功标准（可度量）

- **SC-001**: Dashboard 首屏（含全部自选股报价）渲染 p95 < 2 秒（PRD §7.1）。
- **SC-002**: 报价自动刷新周期稳定 60 秒 ±5 秒。
- **SC-003**: 行情源单次失败时，Dashboard 100% 不崩溃、不弹错，降级展示上次值。
- **SC-004**: 持仓股 100% 排在非持仓之前。
- **SC-005**: 移动端窄屏下关键字段（名称/价/涨跌幅）100% 可读不溢出。

## 8. 假设（Assumptions）

- F5（001）已交付，自选清单读取接口可用。
- 行情数据源能提供分钟级报价快照 + 指数 + K 线（架构基线 06 已锁定候选）。
- 自选股 ≤ 30 只，无需分页 / 虚拟滚动。
- 异动徽章在 F2 落地前为空位，不影响报价优先版可用性（方案 A）。
- 单用户本地，Dashboard 经内网/Tailscale 访问，无公网鉴权。

## Clarifications

> ② clarify 产出，扫 4 类边界（MVP / API / 数据 / 集成），逐条回写。

### Session 2026-05-20

**[MVP 边界]**
- Q：方案 A 下，异动徽章到底算不算 F1 MVP？
  - A：**不算**。F1 MVP = 报价优先版（报价+涨跌幅+市场概览+排序+详情+降级）。异动徽章是 F2 落地后的 F1 增量，FR-015 仅预留展示位。已固化 §2.2 / §2.3。
- Q：单股详情页 K 线（US3）是 F1 MVP 必做吗？
  - A：降为 **P2**。F1 MVP 至少交付列表 + 市场概览（US1/US2 P1）；详情页 K 线可在 F1 内分阶段。
- Q：SD 自带的涨跌榜/Scanner/EOD/热力图等页面是否启用？
  - A：MVP **不启用**，只保留 Dashboard 主列表 + 详情页；其余 SD 页面 v1.1 再考虑。已写入 §2.2。

**[API 边界]（行情数据源）**
- Q：报价快照刷新频率与数据源限频如何协调？
  - A：60 秒拉一次全量自选（≤30 只），远低于数据源限频；失败走降级（FR-008）不重试风暴。
- Q：行情源延迟多少算"陈旧"？
  - A：快照超过 2 个刷新周期（120 秒）未更新 → 标"陈旧数据"。已纳入 QuoteSnapshot 数据状态。
- Q：K 线数据拉多长区间？
  - A：MVP 详情页默认日 K 近 1 年 + 当日分时；更细周期切换推迟 v1.1。

**[数据边界]**
- Q：停牌 / 退市 / 新股无数据如何区分展示？
  - A：统一灰显，文案区分"停牌"/"已退市/无行情"/"加载中"。已回写 Edge Cases / FR-012。
- Q：涨跌幅基准（前收盘 vs 今开）？
  - A：以**前收盘价**为基准算涨跌幅（A 股惯例）。
- Q：指数与个股数据源不一致时？
  - A：各自独立降级，指数失败不影响个股列表，反之亦然。

**[集成边界]**
- Q：F5 读取接口形态？F1 轮询还是订阅？
  - A：F5 提供全量快照同步读取（001 FR-012 已定）；F1 在每个刷新周期重新读 F5 清单 + 拉行情，**自选清单变化在下一周期生效**。
- Q：F6 未就绪时推送状态条怎么处理？
  - A：探测不到 F6 push_status 接口 → 降级隐藏该条，不报错（FR-014）。
- Q：异动徽章位与 F2 的契约？
  - A：F1 预留徽章字段（badge: 空 / 涨停 / 跌停 / 涵盖 / 突破 / 量能），F2（005）按此枚举回填；F1 先全置空。

> 本轮无需用户拍板的阻塞项；方案 A 的"异动徽章推迟"已是既定前提。
