## 四、推荐组合（MVP 初版代码源）

> 站在 7×24 A 股盯盘 AI 助手 = Dashboard + 自然语言选股 + 早盘简报 + 异动预警 的目标。

### 推荐复用矩阵（三件套）

**组合 = TradingAgents-CN（骨架） + go-stock（推送 + LLM 抽象） + TradingAgents 上游（agent 编排） + akshare（数据） + lightweight-charts（K 线）**

| 来源项目 | 拿什么 | 放进我们项目的哪一层 | 理由 |
|---|---|---|---|
| **hsliuping/TradingAgents-CN**（**主 fork 起点**） | FastAPI + Vue3 + Element Plus + MongoDB + Redis 整套；自选股分组数据模型；Tushare/AkShare/BaoStock 多源 fallback；Docker 部署 | **整体骨架** = 后端 + 前端 + 部署 | 已经把英文版中文化、A 股化、加了 dashboard，省 2-3 个月工程 |
| **TauricResearch/TradingAgents**（**agent 编排升级**） | LangGraph 多分析师辩论编排、checkpoint 续跑、多 LLM provider 路由 | **AI 分析层** | 上游 77.6k star，迭代比 CN fork 快，定期同步上游改进 |
| **ArvinLovegood/go-stock**（**告警 + LLM 抽象抄过来**） | `alarm/` 的钉钉推送 + 阈值监控逻辑；多 LLM provider 抽象（DeepSeek/Ollama/SiliconFlow/火山） | **告警 + LLM 适配** 模块 | GPL 传染所以**只抄思路重写**，不要直接 import |
| **freqtrade**（**Telegram bot 范本**） | `freqtrade/rpc/telegram.py` 的 Telegram 双向控制模式 | **推送通道**（除钉钉外加 TG） | 工业级双向交互 bot 模板 |
| **akshare**（**数据底座**） | 直接 pip 装；`stock_zh_a_hist`、龙虎榜、板块、财报 | **数据接入**（冷数据 + 准实时） | 免费 + 持续维护（2026-05 仍周更） |
| **tushare**（**财报补强**） | Pro 财报 + 股东数据 | **数据接入**（深度补强） | 仅在需要财报时调用 |
| **tradingview/lightweight-charts**（**K 线组件**） | npm `lightweight-charts` | **前端图表层** | 1.5k stars 的同类替代都没它快；TradingAgents-CN 的 ECharts 可被它替换 |
| **microsoft/qlib**（**v2 因子库**） | `qlib.contrib.data` 的 Alpha158 因子 | **量化校验层**（可选） | 给"AI 选股"的回测背书用 |

### License 风险检查
- **可直接 fork**：TradingAgents-CN（Apache-2.0，注意 app/frontend 闭源目录要绕开）、TradingAgents（Apache-2.0）、akshare/tushare/qlib/lightweight-charts（MIT/BSD/Apache）
- **不要 fork 只能借鉴重写**：go-stock（GPLv3）、freqtrade（GPLv3）、OpenBB（AGPLv3）

### 一句话方案
> **fork TradingAgents-CN 作为 monorepo 骨架** → 用 **TauricResearch/TradingAgents 上游**替换 / 拉齐 agent 编排 → **重写 go-stock 风格的告警+LLM 抽象层**（避 GPL） → **akshare 当数据底座，tushare 财报补强** → **lightweight-charts 升级前端 K 线**。预估能省 3-4 个月 0→1 工程量。
